# Tools

Scripts and their tests. `/setup-claude` links a few into `~/.claude/` (the statusline, `workspace-lock.sh`, `shell-init.zsh`); the rest run from the checkout. [CLAUDE.md](../CLAUDE.md) lists which test to run after a change.

- **statusline.sh** — Custom Claude Code status line showing model, context window usage (scaled to the `autoCompactWindow` setting, 500k with the `/setup-claude` template; 250k if unset), and both the 5-hour and weekly rate limit windows. With `ANTHROPIC_API_KEY` set and no `rate_limits` (an API-key session) the two bars give way to `cached <bar>` (the cache-read share of all input), `Input <total> / <cost-weighted>` (the weighted figure counts 5-minute cache writes x1.25, 1-hour writes x2 and cache reads x0.1 of a fresh token, base-price multipliers, so an estimate), `Output` and `Cost`, summed from the session's transcript and its subagents' transcripts, cached by their total size (a changed file is re-summed by a detached job, so the figures lag one render). Also writes this account's rate-limit windows to a readings file another tool can turn into meters, one file per account (keyed by a hash of the account id in that session's `.claude.json`). A session on `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY` shares the stored login's `~/.claude.json`, which names the stored login, not the token's or key's account, so it keeps no readings file: such a session neither writes nor borrows windows, even when the token is the stored login's own (an exported token on a single account loses the cross-chat bars), and a key session shows the API view, never the stored login's bars. That is how alternate accounts run (`accounts.zsh`), by design
- **[workspace-lock](workspace-lock/README.md)** — Advisory JSON lock that serializes the mutating work (edits, builds, tests) of independent overnight orchestrators on one machine, over a shared working copy. See the `unattended-run` skill
- **[github-mcp](github-mcp/README.md)** — An optional, guarded setup of GitHub's MCP server: a launcher plus a hook that limits which GitHub writes agents may make, both run from the live checkout, which the guard and launcher require to be reviewed code (clean `main`, `HEAD` on `origin/main`), plus a pinned binary hash, with their tests; its README covers install and token rotation
- **[claude-review](claude-review/README.md)** — Automatic Claude PR review for GitHub Actions, posted by a per-owner reviewer App: inline findings, an overview comment, an APPROVE / REQUEST_CHANGES signal, thread follow-up on `@claude review`, auto-resolve of fixed threads; Claude only reads and posts nothing. The canonical workflow and command other repos copy byte for byte, except the runner and auth lines; this repo runs the same copies. Installed in other repos by `/add-claude-review`
- **cleanup-claude** — `bash tools/cleanup-claude/cleanup.sh [--apply] [--purge-ask] [--keep-ambiguous] [--remove-guard-hook] [--include-security] [--verbose]`: removes what the repo installed on this machine (links that resolve into the checkout, the toolkit's settings.json keys and hook entries after a backup (the security entries stay unless `--include-security`; the github MCP guard hook stays unless `--remove-guard-hook` or `--include-security`), the plain rc `source` lines, runtime state). Dry run by default. Never touches login, Keychain, transcripts or CLAUDE.md; sudo, `claude mcp remove`, npm and Keychain steps are printed, never run. Driven by the project-scoped `/cleanup-claude` skill
- **ait** — `tools/ait.zsh` zsh helpers, loaded by `~/.zshrc` through `source ~/.claude/tools/shell-init.zsh`: `ait` (cd to the checkout), `ait-status` (what `/setup-claude` checks), `ghm-status` (the GitHub MCP lines of `ait-status`: the checkout on a clean `main`, the server binary, the server registration and the guard hook, all at this checkout) and `ghm-test` (the GitHub MCP suites)
- **accounts** — `tools/accounts.zsh`, loaded by `shell-init.zsh` beside `ait.zsh` (macOS only: it reads the Keychain and uses VS Code's macOS paths). Alternate Claude Code accounts without a second config dir: the stored login in `~/.claude` stays the default, and each line of `~/.claude/accounts.conf` (`<name> <kind> <keychain-service>`, kind `oauth` for a `claude setup-token` token or `apikey`) makes `claude-<name>` and `code-<name>` in new shells. Arguments pass straight through. The secret is read from the Keychain in a subshell into that one variable (`CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY`) and `exec` replaces the subshell, so your shell never holds it and nothing prints it; the program and everything it starts (the Bash tool, hooks, MCP servers, extensions) inherit it, as with any environment variable, and only that one variable is set: an `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN` exported in the shell these run in is inherited as well and may outrank it, so keep both out of that shell; a name that a command, function or alias already has is skipped with the reason. `code-<name>` runs `code --user-data-dir ~/.vscode-accounts/<name>`, its own VS Code instance beside the main one, whose `User/` folder links to the main `settings.json`, `keybindings.json`, `snippets/` and `mcp.json` (links, so a change made in the account's window goes through them into the main folder, and the MCP servers of `mcp.json` start with the secret in their environment; the launcher itself writes only under `~/.vscode-accounts/<name>`; extensions are shared, since VS Code keeps them in `~/.vscode/extensions` whatever the data dir). The file is read by `install-copies.sh accounts`: never sourced, each field checked, a bad line reported and skipped, a file you do not own or others can write, or one in a `~/.claude` that others can write, refused whole (a symlinked file is judged by its target). Add and remove accounts with the `/add-account` and `/remove-account` skills. Not verified: that the Claude Code extension inside a `code-<name>` window uses the account's variable, and whether the macOS `code` CLI hands its environment to the app in a way that shows the secret in another process's arguments for a moment. Tests: `bash tools/test-ait.sh`
- **install-copies.sh** — `bash tools/install-copies.sh status`: reports what is wired outside the checkout (the github MCP checkout, binary, server registration and guard hook, install-time settings, the `~/.zshrc` line, `~/.claude/accounts.conf` and whether each account's Keychain item exists (asked without reading the secret), the links, any hook or lock script that is not executable, and any hook `settings.json` does not run); `/setup-claude check` runs it. `accounts` prints the valid lines of `~/.claude/accounts.conf` (what `accounts.zsh` loads). `roster` lists what `/setup-claude` links: the agents, hooks, rules and skills committed at `HEAD`, never an untracked file
- **test-all.sh** — `bash tools/test-all.sh [--quick] [NAME…]`: runs every tool and hook test suite and prints a pass/fail table. Each hook (`secret-detector`, `destructive-blocker`, `git-mcp-guard`, …) has its suite under `tools/<name>/`; see [CLAUDE.md](../CLAUDE.md) for which to run after a change
