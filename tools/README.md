# Tools

Scripts and their tests. `/setup-claude` links a few into `~/.claude/` (the statusline, `workspace-lock.sh`, `shell-init.zsh`); the rest run from the checkout. [CLAUDE.md](../CLAUDE.md) lists which test to run after a change.

- **statusline.sh** — Custom Claude Code status line showing model, context window usage (scaled to the `autoCompactWindow` setting, 500k with the `/setup-claude` template; 250k if unset), and both the 5-hour and weekly rate limit windows. With `ANTHROPIC_API_KEY` set and no `rate_limits` (an API-key session) the two bars give way to `Input <total> <bar> <N>% hot`, `Output` and `Cost`, summed from the session's transcript and its subagents' transcripts, cached by their total size (a changed file is re-summed by a detached job, so the figures lag one render). Also writes this account's rate-limit windows to a readings file another tool can turn into meters
- **[workspace-lock](workspace-lock/README.md)** — Advisory JSON lock that serializes the mutating work (edits, builds, tests) of independent overnight orchestrators on one machine, over a shared working copy. See the `unattended-run` skill
- **[github-mcp](github-mcp/README.md)** — An optional, guarded setup of GitHub's MCP server: a launcher plus a hook that limits which GitHub writes agents may make, both run from the live checkout, which the guard and launcher require to be on a clean `main`, with their tests; its README covers install and token rotation
- **[claude-review](claude-review/README.md)** — Automatic Claude PR review for GitHub Actions, posted by a per-owner reviewer App: inline findings, an overview comment, an APPROVE / REQUEST_CHANGES signal, thread follow-up on `@claude review`, auto-resolve of fixed threads; Claude only reads and posts nothing. The canonical workflow and command other repos copy byte for byte, except the runner and auth lines; this repo runs the same copies. Installed in other repos by `/add-claude-review`
- **cleanup-claude** — `bash tools/cleanup-claude/cleanup.sh [--apply] [--config-dir DIR] [--purge-ask] [--keep-ambiguous] [--include-security] [--verbose]`: removes what the repo installed on this machine (links that resolve into the checkout, the toolkit's settings.json keys and hook entries after a backup (the security entries stay unless `--include-security`), the plain rc `source` lines, runtime state). Dry run by default. Never touches login, Keychain, transcripts or CLAUDE.md; sudo, `claude mcp remove`, npm and Keychain steps are printed, never run. Driven by the project-scoped `/cleanup-claude` skill
- **ait** — `tools/ait.zsh` zsh helpers, loaded by `~/.zshrc` through `source ~/.claude/tools/shell-init.zsh`: `ait` (cd to the checkout), `ait-status` (what `/setup-claude` checks), `ghm-status` (the GitHub MCP lines of `ait-status`: the checkout on a clean `main`, the server binary, the server registration and the guard hook, all at this checkout) and `ghm-test` (the GitHub MCP suites)
- **install-copies.sh** — `bash tools/install-copies.sh status`: reports what is wired outside the checkout (the github MCP checkout, binary, server registration and guard hook, install-time settings, the `~/.zshrc` line); `/setup-claude check` runs it
- **test-all.sh** — `bash tools/test-all.sh [--quick] [NAME…]`: runs every tool and hook test suite and prints a pass/fail table. Each hook (`secret-detector`, `destructive-blocker`, `git-mcp-guard`, …) has its suite under `tools/<name>/`; see [CLAUDE.md](../CLAUDE.md) for which to run after a change
